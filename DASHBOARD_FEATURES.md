# CiteBrief Dashboard Feature Plan

## Goal

Make CiteBrief feel worth the paid price by moving the app from a simple AI report generator to an AI visibility command center for founders, SaaS teams, and agencies.

The dashboard should answer four questions every time a user logs in:

1. Are we improving or declining?
2. Which competitors are winning?
3. What changed since the last run?
4. What should we do next?

## Product Positioning

CiteBrief should not feel like a thin reporting tool. It should feel like the place a user goes to monitor, explain, and improve how their brand appears across AI search engines.

For agencies, the dashboard must also feel client-ready. A user should be able to open CiteBrief during a client call and explain:

- Where the client stands.
- Who is beating them.
- Which prompts matter most.
- What actions should be taken this week.
- What progress has happened since the last report.

## Dashboard Principles

- Show business meaning first, raw data second.
- Prioritize change over static snapshots.
- Turn reports into actions.
- Make every paid plan feel visibly valuable.
- Make agency workflows feel native, not bolted on.
- Avoid vanity metrics that do not help users make decisions.

## Core Dashboard Areas

### 1. Executive Overview

The main dashboard should become the first high-value screen after login.

It should include:

- Overall AI visibility score.
- Week-over-week or month-over-month movement.
- Total brands monitored.
- Active prompts tracked.
- Engines monitored.
- Competitor mentions.
- Open opportunities.
- Active risks.
- Latest report status.
- Suggested next action.

The overview should clearly show whether the account is improving, flat, or declining.

### 2. Brand Scorecards

Each brand should have a compact scorecard that summarizes health and momentum.

Each scorecard should show:

- Brand name and site.
- AI visibility score.
- Mention share.
- Citation share.
- Competitor gap.
- Number of winning prompts.
- Number of losing prompts.
- Open opportunities.
- Risk level.
- Last run date.
- Next scheduled run.

For agencies, scorecards should support quick scanning across multiple clients.

Recommended states:

- Healthy.
- Needs attention.
- At risk.
- New data pending.
- Run failed.

### 3. Competitor Intelligence

This should become one of the main value drivers of the product.

The dashboard should show:

- Which competitors are mentioned most often.
- Which competitors are recommended as the top choice.
- Which competitors receive citations.
- Which competitor URLs are cited.
- Which prompts competitors win.
- Which engines favor which competitors.
- Why competitors appear to be winning.

Useful views:

- Competitor leaderboard.
- Competitor by engine.
- Competitor by prompt.
- Competitor cited pages.
- Competitor movement since last run.

This section should help users understand not just who is winning, but what to copy, counter, or improve.

### 4. Opportunity Queue

Reports should create an action queue automatically.

Each opportunity should include:

- Opportunity title.
- Affected brand.
- Related prompt.
- Related engine.
- Impact level.
- Effort level.
- Suggested action.
- Reason the opportunity exists.
- Suggested page or content to create.
- Owner.
- Status.

Example opportunities:

- Create a comparison page against the winning competitor.
- Add a stronger alternatives page.
- Improve pricing page clarity.
- Add integration content.
- Add customer proof or case studies.
- Improve homepage category positioning.
- Add schema or structured data.
- Refresh outdated content cited by AI engines.

Opportunity statuses:

- Open.
- Planned.
- In progress.
- Done.
- Dismissed.

### 5. Risk Alerts

The dashboard should clearly show problems that need attention.

Risk examples:

- Brand disappeared from a high-intent prompt.
- Competitor overtook the brand.
- AI gave an incorrect answer about the brand.
- AI cited an outdated page.
- Important prompt failed.
- Report quality dropped.
- Citation source changed negatively.
- Sentiment became weaker.

Each risk should include:

- Severity.
- What happened.
- Why it matters.
- Recommended fix.
- First seen date.
- Last seen date.
- Affected prompts.
- Affected engines.

### 6. Prompt Performance View

Prompts should feel like tracked business assets.

Each prompt should show:

- Prompt text.
- Mix type.
- Visibility score.
- Mentioned or not mentioned.
- Brand position if available.
- Competitors mentioned.
- Cited URLs.
- Engines checked.
- Last answer summary.
- Movement since previous run.
- Recheck option.

Useful filters:

- Winning prompts.
- Losing prompts.
- No mention.
- Competitor wins.
- High-intent prompts.
- Recently changed.
- Failed checks.

### 7. Engine Breakdown

Users should understand how performance differs across engines.

Supported engines:

- ChatGPT.
- Gemini.
- Grok.
- AI Overviews.

For each engine, show:

- Mention rate.
- Citation rate.
- Average visibility score.
- Top cited URLs.
- Top competitors.
- Prompts where brand appears.
- Prompts where brand is missing.
- Recent changes.
- Run reliability.

This view helps justify why CiteBrief monitors multiple AI-search surfaces.

### 8. Client Reporting Center

This is essential for agencies and higher-priced plans.

The reporting center should support:

- Branded PDF export.
- Shareable report link.
- Monthly client summary.
- White-label agency branding for higher plans.
- Report history.
- Notes and recommendations.
- Client-ready executive summary.
- Before-and-after movement.

Each report should include:

- What changed.
- What improved.
- What declined.
- Which competitors are winning.
- What actions are recommended.
- What was completed since the last report.

### 9. Agency Workspace

Agency users need a dashboard built around multiple clients.

The agency workspace should include:

- Multi-brand overview.
- Client owner.
- Client status.
- Priority sorting.
- Upcoming scheduled runs.
- Recheck credit usage.
- Report export status.
- Client notes.
- Assigned opportunities.
- At-risk clients.

Recommended agency views:

- All clients.
- Needs attention.
- Reports due.
- Recent wins.
- Competitor threats.
- Usage and credits.

### 10. Action History

Users should be able to see what changed over time.

Track:

- Runs completed.
- Reports generated.
- Opportunities created.
- Opportunities completed.
- Risks opened.
- Risks resolved.
- Prompts added or changed.
- Competitors added or changed.
- Manual rechecks used.

This helps justify ongoing subscription value.

## Plan-Based Dashboard Value

### Starter

Starter should feel useful for one serious brand, not like a stripped trial.

Include:

- One-brand executive overview.
- Prompt performance.
- Latest report.
- Basic competitor mentions.
- Basic opportunities.
- Two monthly rechecks.

Do not include:

- Multi-client agency views.
- White-label reports.
- Advanced competitor intelligence.

### Agency

Agency must feel worth $249/month.

Include:

- Multi-brand dashboard.
- Brand scorecards.
- Competitor leaderboard.
- Opportunity queue.
- Risk alerts.
- Client-ready exports.
- Client owner field.
- Usage and recheck credit visibility.
- Ten monthly rechecks.

This plan should feel like the default plan for agencies managing several clients.

### Studio

Studio should justify a much higher price by adding operating leverage.

Include:

- Everything in Agency.
- More brands.
- More prompts.
- Larger recheck allowance.
- White-label reporting.
- Advanced competitor intelligence.
- Priority opportunity scoring.
- Client reporting center.
- Deeper history.
- More seats.

Studio should feel like an agency growth plan, not simply a higher usage tier.

### Enterprise

Enterprise should focus on control, scale, compliance, and support.

Include:

- Everything in Studio.
- Custom limits.
- Advanced access control.
- Audit logs.
- SSO-ready architecture.
- Custom reporting needs.
- Priority support.
- Custom onboarding.

## Highest Priority Implementation Order

### Phase 1: Make The Dashboard Feel Valuable

1. Executive overview.
2. Brand scorecards.
3. Prompt performance table.
4. Basic competitor leaderboard.
5. Opportunity queue.

This phase is the minimum needed to make the product feel stronger at $249/month.

### Phase 2: Make It Agency-Ready

1. Multi-brand agency overview.
2. Client owner and client status.
3. Client-ready report export.
4. Risk alerts.
5. Recheck credit visibility.

This phase makes the Agency plan easier to sell.

### Phase 3: Make Studio Worth More

1. White-label reporting.
2. Advanced competitor intelligence.
3. Opportunity scoring.
4. Report history and action history.
5. Deeper trend charts.

This phase supports higher pricing for Studio.

## Must-Have Dashboard Metrics

- Visibility score.
- Mention share.
- Citation share.
- Competitor share.
- Prompt win rate.
- Prompt loss rate.
- Engine coverage.
- Opportunity count.
- Risk count.
- Run success rate. _(Overview KPI: complete+partial / finished latest runs)_
- Last run date.
- Next scheduled run.
- Recheck credits used.
- Top cited URLs. _(Engine breakdown + competitor intelligence)_

## Suggested Dashboard Navigation

Recommended app navigation:

- Overview.
- Brands.
- Prompts.
- Competitors.
- Opportunities.
- Risks.
- Reports.
- Settings.

For agencies:

- Clients can be represented as brands.
- The UI should use agency-friendly wording where useful, such as client owner, client status, and client report.

## What Not To Build Yet

Avoid adding features that create complexity without immediate revenue value.

Do not prioritize:

- Full project management.
- Complex task dependencies.
- Real-time chat.
- Social scheduling.
- Full SEO crawler.
- Generic keyword tracking.
- Large CRM features.
- Website CMS features.

CiteBrief should stay focused on AI visibility, competitor intelligence, and action recommendations.

## Success Criteria

The dashboard is successful when:

- A new paid user understands value within 60 seconds.
- An agency can explain a client’s AI visibility in one screen.
- Every report produces clear next actions.
- Users can see improvement or decline over time.
- The Agency plan feels meaningfully stronger than Starter.
- Studio feels like a serious operating layer for agencies.
- Users log in between reports because the dashboard itself is useful.
